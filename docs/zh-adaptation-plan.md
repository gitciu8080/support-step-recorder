# 中文与智能步骤记录改造计划

日期：2026-10-09。目标环境：Linux KDE Wayland；视觉模型：现有 MI50。
本文保留最初调研方案；下方实施状态记录本次落实结果。

## 本次实施状态

- 已增加简体中文界面、HTML 文案与内嵌 CJK 字体，并优先识别桌面 `LANGUAGE`。字体许可证与声明位于 GUI assets。
- 已增加无损/高清/小体积截图选项与原尺寸查看；保留源帧尺寸，不自动裁掉黑色内容。截图写入队列有上限，满时等待写入而不丢弃截图，写入线程不可用时显示错误，导出失败不会覆盖已有 ZIP。
- 已接入 Fcitx5 原生插件和 AT-SPI 文本变化监听。Fcitx5 实机测试用拼音产生了“快递小助手”，并验证删除、粘贴与密码过滤；真实 Qt 控件也验证了辅助功能中文文本与删除事件。覆盖范围依赖应用暴露的能力，不支持时降级为“内容未确认”。
- 已补充输入停顿及停止时的截图，并增加带时间戳的操作前帧和点击后延迟帧；下一次鼠标按下/键盘按下会取消后帧。只有时间符合条件时才作为对应画面使用。后帧是短暂等待后的证据，不保证整个任务已经完成。
- 已接入 MI50 的实际视觉接口，通过非敏感测试图取得“在搜索框中输入‘快递小助手’”及画面可见结果。自动录制后分析、失败重试、取消、人工修改和重新导出均已接入；GUI、JSON、HTML 统一选择最终描述。
- 本机已安装构建依赖、输入权限规则与 Fcitx5 插件，需管理员的操作均通过 pkexec。密钥仅存放用户私有配置文件。
- 尚需用户在日常目标应用中实际录制一轮，确认桌面共享选区、输入法和应用的组合表现；已有自动测试与独立实机输入/视觉联调不能替代所有应用的完整桌面验收。
- 最终检查：22 项自动测试通过，严格 Clippy 检查通过，中文版 GUI 编译、启动与字体显示检查通过。MI50 非敏感画面调用返回有效中文步骤描述。最终程序位于 `target/debug/ssr`，已在本机打开。

## 项目现状与问题定位

项目是 Rust workspace：`ssr-core` 负责输入、截图、会话和导出，`ssr-gui` 使用 egui/eframe 展示、回放和保存。Wayland 输入来自 evdev，截图来自桌面门户及 PipeWire；导出 ZIP 包含 HTML、JSON 和 WebP。

| 需求 | 代码证据 | 结论 |
| --- | --- | --- |
| 中文界面 | `i18n.rs` 仅有 Fr/En，GUI 使用二选一文案，未配置中文字体 | 需要同时增加语言、字体和报告翻译 |
| 截图清晰度 | `recorder.rs` 固定 quality=55，`capture.rs` 设置 lossless=0 | 当前有损压缩是明确可改进点；仍需检查源帧分辨率与缩放 |
| 中文记录 | `text.rs` 将物理键映射为 US 字符，`session.rs` 将其直接存为 Text | 拼音在采集阶段就被误当成最终文字，不是导出编码问题 |
| 智能描述 | `model.rs` 仅生成模板句；GUI、HTML 都重新调用 build_description | 只修改 Step.description 不会让智能描述在所有界面生效 |
| 时序证据 | 输入事件是 MouseUp；文本步骤没有截图；停止只刷新文字 | 无法保证截图是操作前状态，也缺少最后一次输入的画面 |

PipeWire 参数首选 1920×1080，但允许协商其他尺寸；不能仅凭该值认定所有截图被缩到 1080p。流帧率已由首选 5 fps 提高到 60 fps，帧保留间隔由 200 ms 缩短到 16 ms；实际帧率由桌面协商决定。

## 实施顺序

### 1. 先验证中文文本来源，明确可支持范围

- 在实际 KDE Wayland 会话确认输入法及版本，选浏览器输入框和一个 Qt 应用复现“快递小助手”。
- 优先验证 AT-SPI 焦点控件的文本接口与文本变化事件，记录控件身份、变化范围及前后值，区分新增输入与原有内容。官方 Text 接口提供文本读取能力，但目标应用是否暴露、组合态如何表现，必须实测。
- 若应用未暴露所需信息，再针对实际输入法评估提交事件的集成。例如 Fcitx5 插件路径需要独立验证；不能假定普通 D-Bus 监听就能获得所有应用的最终提交文字。
- 物理按键、输入法提交、控件文本和视觉识别使用不同来源标记。禁止把物理拼音自动标成已确认中文，也不做拼音猜词替换。
- 无可靠文本来源时，显示“发生文字输入，内容未确认”；视觉识别结果作为可编辑建议，保留来源。拿不到中文并不等于修复完成。

验收：在明确支持的应用中，输入“快递小助手”后，GUI、JSON、HTML 均保留这五个汉字；覆盖候选选择、中英混输、退格、替换选区、粘贴、多次提交、切换焦点和输入后直接停止。无支持的应用必须准确说明降级状态。避免采集密码控件内容。

### 2. 简体中文界面和报告

- 增加 `Lang::ZhCn`，识别中文 locale；语言选择扩展为中文/English/Français。
- 将二选一文案迁移为稳定的翻译键或三语言资源，覆盖按钮、状态、错误、保存提示、步骤信息、回放和图片替代文本。
- 为 egui 配置有明确许可证的中文字体及回退；验证中文窗口标题、长文本和不同 DPI。
- HTML 使用适当的中文语言标记，统一 GUI 与导出的描述选择规则。

验收：中文环境默认中文，切换语言即时生效，中文不显示方框，报告离线可读，原有英法文功能保留。

### 3. 原尺寸高清截图与可靠时序

- 提供无损 WebP、高质量有损和小体积选项；面向文字记录优先无损，沿用后台写入。
- 检查源帧实际尺寸、显示器缩放、裁剪及报告显示；增加原尺寸查看，不能仅依靠提高编码质量修复源图模糊。
- 保存不带永久红圈的原始画面，点击标记作为展示叠层；为模型保留清晰文字。
- 为输入完成/停顿和停止录制补充截图；记录帧时间及关联步骤，避免把下一次操作的画面归给前一步。
- 设计操作前后截图：保留最近的前帧，等待操作后界面稳定或达到超时取得后帧。缺失一侧时明确标记，不能声称操作成功。
- 图像队列保持资源上限，满时通过等待施加背压；输入采集与界面运行在独立线程。持续超负载时步骤处理可能延迟，不能保证每一步都有不同的画面。导出应报告写入失败，不应悄悄省略。

验收：小字号中文在 100% 查看时可读；无损编码往返像素一致；高 DPI 下坐标与裁剪一致；快速点击与最后一次输入不会错配或丢图。比较文件体积、内存和录制响应时间。

### 4. 接入 MI50 视觉模型

依据本地 `mi50-models` 手册，目标接口为 MI50 的 `:8200/v1/chat/completions`，模型候选 `Qwen3.6-35B-A3B`，图像使用 base64 data URL。服务地址、凭据、模型可配置；正式联调通过 `/v1/models` 和一张非敏感测试图验证实际服务，不以手册替代在线验证。

- 第一版采用停止录制后异步分析，支持逐步重试、取消和继续导出，避免推理阻塞录制。
- 输入：前后截图、窗口/应用信息、可用的点击位置、已确认文本和相邻步骤。Wayland 当前没有全局点击坐标，不得捏造。
- 输出：中文动作描述、可见结果、证据与不确定项。示例：证据充分时“在搜索框输入‘快递小助手’，点击搜索”；只有点击画面时不补写“搜索成功”。
- 模型推断作为独立可选字段保留，原始事件不覆盖；提供用户编辑值，统一 GUI/HTML/JSON 的读取路径与旧数据兼容。
- 对模型最终答复做结构校验；只有 reasoning_content、无最终 content 时按未完成处理，不能直接展示为步骤结论。
- 配置超时、有限重试、失败状态和重新分析。启用功能时说明截图会发送到配置的 MI50；密钥不进入仓库、日志或导出包。截图中的指令只作为画面内容，不作为模型操作指令。

验收：真实图像调用成功并生成有依据的中文步骤；断网、鉴权失败、超时或输出格式错误均不损坏原始会话；智能描述在预览和导出中一致，可修订。

## 数据与模块边界

保留输入与截图后端；新增文本来源抽象、截图质量配置及独立的视觉分析模块。Step 的新增字段应可选并兼容旧 JSON，包含文本来源、画面关联、分析状态、智能描述和人工修订。原始按键如需诊断，应显式启用并与正文分离。

推荐交付节奏：中文文本可行性验证 → 中文界面与高清截图 → 正式文本后端 → MI50 分析及报告整合。文本能力验证应先行，避免完成大量界面工作后才发现目标应用缺少可读取的提交文字。
